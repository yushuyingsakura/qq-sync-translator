# 测试与兼容性

v0.1.1 共通过 31 项自动化测试。测试使用合成文本和临时设置目录，不需要 QQ 账号或翻译服务密钥。

## 运行

使用 Node.js 20 或更高版本，在仓库根目录执行：

```sh
npm ci
npm test
```

仅运行核心逻辑与主进程桥接测试，不需要安装开发依赖：

```sh
npm run test:core
```

安装插件本身不需要运行 npm。运行源码无额外 npm 依赖；Happy DOM 仅用于开发测试。

## 自动化覆盖

- 配置、启用同意选项、服务地址和长度限制。
- DeepL / LibreTranslate 请求格式、超时、限流、响应校验与错误信息处理。
- 请求串行、在途合并、内存缓存、暂停及设置变化时取消旧结果。
- 收信与发信区分、引用与转发排除、原文保留、纯文本渲染和失败重试。
- 虚拟列表节点复用、可见性过滤与新消息观察。
- 密钥存储接口、设置保存及 IPC 调用来源检查。
- 真实本地 HTTP 测试服务与主进程桥接的往返请求。

本次原生 QQ 收信适配的回归覆盖包括：`text-element--other` 正文标记、自己消息含嵌套标记时仍排除、正文根节点直接文字与换行，以及旧默认选择器迁移。

## 实机验证边界

已在 Windows QQ NT **9.9.33-52230** 与 LiteLoaderQQNT **1.4.1** 环境中验证插件加载、原生消息识别和译文生成。其他 QQ 版本或主题可能需要调整选择器。

另使用真实 LibreTranslate 模型验证了中英日六个翻译方向及离线推理。接口连通测试不代表翻译质量达到人工校对水平，部分语言组合会经过英语中转。DeepL 目前只验证请求构造，未使用真实 API 账号验证。

自动化测试中的 Electron 与 `safeStorage` 使用替身，不能替代每个 Windows 环境下的实际加载与密钥加密验证。DOM 测试使用受控夹具，也不能覆盖所有 QQ 页面变化。

提交兼容性问题时，请提供 QQ / LiteLoader 版本和插件设置中的诊断数量；不要附带 API Key、设置文件或未脱敏的聊天记录。
